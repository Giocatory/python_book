# Как пользоваться этой книгой

## Принцип изложения

Каждая глава построена по одной схеме: **цель главы → темы → подтемы → пояснение → код → типичные ошибки → контрольные вопросы → практика**. Ничего не предполагается известным заранее: если понятие используется, оно либо объяснено выше, либо дана ссылка на главу.

Читать нужно последовательно. Главы 1–15 — это фундамент, который нельзя «пролистать по диагонали»: 80% проблем на уровне Middle растут из пропущенных основ (модель памяти, изменяемость, области видимости, итераторы).

## Условные обозначения

> [!NOTE] Блок «Важно» — то, что нужно понять и запомнить. Обычно это внутреннее устройство или правило, нарушение которого дорого стоит.

> [!WARNING] Блок «Предупреждение» — типичная ошибка новичка или опасная практика, которая ломает продакшен.

> [!TIP] Блок «Совет» — приём, ускоряющий работу или делающий код чище.

> [!TASK] Блок «Практика» — обязательное задание. Без выполнения практика не считается пройденной.

## Правило 30/70

30% времени — чтение и разбор, 70% — набор кода руками. Не копипастить: печатать. Моторная память на синтаксис формируется только так. Каждую задачу решай дважды: первый раз — как получилось, второй — как правильно (после разбора ошибок).

## Что нужно на старте

- Компьютер с Windows 10+, macOS 12+ или Linux, 8 ГБ ОЗУ (комфортно — 16 ГБ).
- Права администратора для установки ПО.
- Интернет для загрузки дистрибутивов и пакетов.
- 1–2 часа в день. При таком темпе части I–VI занимают ~4–5 месяцев.

## Требования к результату

Глава считается пройденной, если ты можешь: (1) объяснить тему своими словами без подглядывания, (2) написать код по памяти, (3) ответить на контрольные вопросы, (4) выполнить практику. Если хотя бы один пункт не выполнен — глава не пройдена.

# Глава 1. Что такое Python и как исполняется код

**Цель главы:** понять, что происходит между сохранением файла `.py` и появлением результата на экране. Без этого установка и ошибки будут магией.

## 1.1. Программа, язык, транслятор

### 1.1.1. Что такое программа

Программа — это текст на формальном языке, описывающий последовательность действий. Процессор понимает только машинные команды — числа. Значит, между твоим текстом и процессором обязательно стоит переводчик.

### 1.1.2. Компиляция и интерпретация

Компилятор (C, Go, Rust) переводит весь исходник в машинный код заранее, создавая исполняемый файл. Интерпретатор читает и выполняет код построчно во время запуска. Python относится ко второму классу, но с важным нюансом: он сначала компилирует исходник в промежуточное представление — **байт-код**, а уже его исполняет виртуальная машина.

### 1.1.3. Как Python исполняет файл на самом деле

1. Ты запускаешь `python main.py`.
2. Интерпретатор читает файл, проверяет синтаксис и строит AST (абстрактное синтаксическое дерево).
3. AST компилируется в байт-код — набор простых инструкций вида `LOAD_CONST`, `CALL`.
4. Виртуальная машина CPython в цикле исполняет эти инструкции.
5. Байт-код импортируемых модулей кэшируется в папке `__pycache__` в файлы `.pyc`, чтобы при следующем запуске не компилировать заново.

> [!NOTE] `__pycache__` — это служебный кэш, не «мусор» и не вирус. Его добавляют в `.gitignore`. Удаление безопасно: он пересоздастся.

Посмотреть байт-код можно так:

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```

## 1.2. Реализации и версии

### 1.2.1. CPython и альтернативы

**CPython** — эталонная реализация на C, именно её ты скачаешь с python.org и именно её имеют в виду, говоря «Python». Альтернативы: PyPy (JIT-компиляция, быстрее на CPU-задачах), MicroPython (микроконтроллеры), GraalPy. В этой книге — только CPython.

### 1.2.2. Как читать номера версий

Версия имеет вид `3.13.2`: мажорная (3), минорная (13), патч (2). Мажорная меняется при несовместимых изменениях (переход 2→7 был болезненным), минорная — раз в год с новыми возможностями, патч — только исправления багов и безопасности.

> [!WARNING] Python 2 не поддерживается с 2020 года. Любой туториал с `print "hello"` без скобок — устаревший, закрывай его.

### 1.2.3. Какую версию ставить

Ставь актуальную стабильную минорную версию с python.org (линейка 3.12 и новее). Не бери самую свежую в день релиза: часть библиотек ещё не собрала бинарные колёса. Для рабочих проектов фиксируй версию в файле `.python-version` и в `pyproject.toml` (глава 21).

### 1.2.4. Про GIL и free-threading — заранее

В CPython есть GIL — глобальная блокировка интерпретатора, из-за которой в одном процессе только один поток исполняет Python-код. Начиная с 3.13 существуют сборки без GIL (free-threaded). Для обучения и продакшена используй обычную сборку; тема подробно разбирается в главе 36.

## 1.3. Где применяется Python

- **Backend и API:** FastAPI, Django — то, чему посвящена половина книги.
- **Data Science и ML:** pandas, scikit-learn, PyTorch.
- **Автоматизация и DevOps:** скрипты, парсеры, CI-инструменты.
- **Аналитика и отчётность:** обработка Excel/PDF, генерация документов.

Python медленнее C в чистых вычислениях, но выигрывает в скорости разработки, а тяжёлые операции делегирует библиотекам на C/Rust. Отсюда правило: Python — клей между быстрыми компонентами.

## 1.4. Контрольные вопросы

1. Чем байт-код отличается от машинного кода?
2. Зачем нужна папка `__pycache__` и что будет, если её удалить?
3. Что означает вторая цифра в版本号 версии 3.13.2?
4. Почему Python называют интерпретируемым, если он компилирует код?

## 1.5. Практика

# Глава 2. Установка Python и настройка окружения

**Цель главы:** получить работающий интерпретатор, точно знать, где он лежит, и уметь запускать нужную версию.

## 2.1. Что именно мы устанавливаем

Установка даёт три вещи: сам интерпретатор (`python.exe` / `python3`), стандартную библиотеку и пакетный менеджер `pip`. Дополнительно на Windows ставится лаунчер `py`, который умеет выбирать версию.

## 2.2. Windows: пошагово

### 2.2.1. Способ 1 — официальный установщик (рекомендуется новичку)

1. Открой `https://www.python.org/downloads/windows/`.
2. Скачай **Windows installer (64-bit)** актуальной стабильной версии.
3. Запусти файл. **На первом экране обязательно поставь галочку «Add python.exe to PATH»** — без неё команда `python` не будет находиться в терминале.
4. Нажми «Install Now». Дождись окончания и «Setup was successful».
5. Если появится кнопка «Disable path length limit» — нажми: снимается ограничение длины пути в 260 символов.
6. Закрой и заново открой терминал (переменные окружения читаются при старте).

### 2.2.2. Способ 2 — winget из терминала

```powershell
winget install --id Python.Python.3.13 -e
```

### 2.2.3. Проверка

```powershell
python --version
py --version
py -0p
pip --version
```

`py -0p` покажет список установленных версий и пути к ним — незаменимо, когда версий несколько.

> [!WARNING] Не ставь Python из Microsoft Store для разработки: у него перенаправленные пути и ограничения на запись, из-за которых ломается часть инструментов. Если команда `python` открывает Store — отключи «Псевдонимы выполнения приложения» в параметрах Windows.

### 2.2.4. Если `python` не найден

Причина почти всегда в PATH. Варианты: (1) переустановить с галочкой PATH; (2) использовать лаунчер `py` вместо `python`; (3) вручную добавить в PATH два каталога — с `python.exe` и его подкаталог `Scripts`.

## 2.3. macOS

### 2.3.1. Homebrew

```bash
brew install python@3.13
python3 --version
```

### 2.3.2. Официальный pkg

Скачай установщик с python.org и запусти — он ставит Python в `/Library/Frameworks/Python.framework` и добавляет симлинки.

> [!WARNING] В macOS есть системный Python. Никогда не удаляй его и не ставь пакеты в него — от него зависят компоненты ОС. Всегда работай в виртуальном окружении (глава 21).

## 2.4. Linux

### 2.4.1. Debian / Ubuntu

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip build-essential
python3 --version
```

### 2.4.2. Fedora / RHEL

```bash
sudo dnf install -y python3 python3-pip python3-devel gcc
```

### 2.4.3. Нужна другая версия

Штатные репозитории часто отстают. Используй `uv` или `pyenv` (см. 2.5) — они собирают/скачивают нужную версию в домашний каталог, не трогая системную.

> [!WARNING] Никогда не выполняй `sudo pip install`. Это ломает системные пакеты. В свежих дистрибутивах стоит защита PEP 668, и обход через `--break-system-packages` — почти всегда ошибка. Правильный путь — venv.

## 2.5. Управление несколькими версиями: uv и pyenv

### 2.5.1. uv — современный стандарт

`uv` — быстрый менеджер на Rust, умеет ставить сам Python, создавать окружения и ставить пакеты.

```bash
# Linux/macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows PowerShell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

uv python install 3.13
uv python list
```

### 2.5.2. pyenv

Классический вариант для Linux/macOS: `pyenv install 3.13.2`, `pyenv global 3.13.2`, `pyenv local 3.12.8` (запишет `.python-version` в проект). На Windows — `pyenv-win`.

## 2.6. Где лежит интерпретатор

```bash
python -c "import sys; print(sys.executable); print(sys.version)"
```

Windows: `where python`. Linux/macOS: `which -a python3`.

> [!NOTE] `sys.executable` — источник истины. Если IDE «не видит» установленный пакет, в 90% случаев она использует другой интерпретатор. Сравни путь в IDE с выводом этой команды.

## 2.7. Первый pip-запуск

```bash
python -m pip --version
python -m pip install --upgrade pip
python -m pip install requests
python -m pip list
```

Форма `python -m pip` предпочтительнее просто `pip`: она гарантированно относится к выбранному интерпретатору.

## 2.8. Диагностика типовых проблем

| Симптом | Причина | Решение |
|---|---|---|
| `python не является внутренней командой` | нет в PATH | переустановка с галочкой PATH или `py` |
| Открывается Microsoft Store | псевдонимы приложения | отключить их в параметрах Windows |
| `pip: command not found` | нет Scripts в PATH | `python -m pip` |
| `externally-managed-environment` | PEP 668 | создать venv |
| Пакет установлен, но `ModuleNotFoundError` | другой интерпретатор | сверить `sys.executable` |
| `SSL: CERTIFICATE_VERIFY_FAILED` (macOS) | нет корневых сертификатов | запустить `Install Certificates.command` |

# Глава 3. Терминал: рабочий минимум

**Цель главы:** перестать бояться чёрного окна. Терминал — основной инструмент backend-инженера.

## 3.1. Оболочка и терминал

Терминал — окно для ввода текста. Оболочка (shell) — программа, которая этот текст разбирает и запускает. В Windows это PowerShell (современный) или cmd (устаревший), в Linux/macOS — bash или zsh. Команды у них разные, но принципы одинаковы.

> [!TIP] На Windows поставь **Windows Terminal** и **PowerShell 7**. Работать станет заметно приятнее.

## 3.2. Навигация

```bash
pwd                 # где я (PowerShell: pwd работает)
ls                  # что здесь (PowerShell: ls / dir)
ls -la              # включая скрытые, с правами и размерами
cd projects         # перейти в подпапку
cd ..               # на уровень выше
cd ~                # домой
cd -                # назад (bash)
```

**Абсолютный путь** начинается от корня (`/home/user/app` или `C:\app`), **относительный** — от текущей папки. `.` — текущая папка, `..` — родительская.

## 3.3. Операции с файлами

| Действие | bash / zsh | PowerShell |
|---|---|---|
| Создать папку | `mkdir app` | `mkdir app` |
| Создать файл | `touch main.py` | `New-Item main.py` |
| Показать файл | `cat main.py` | `Get-Content main.py` |
| Копировать | `cp a.py b.py` | `Copy-Item a.py b.py` |
| Переместить | `mv a.py src/` | `Move-Item a.py src/` |
| Удалить файл | `rm a.py` | `Remove-Item a.py` |
| Удалить папку | `rm -r tmp` | `Remove-Item tmp -Recurse` |

> [!WARNING] `rm -rf` не спрашивает подтверждения и не отправляет в корзину. Всегда сначала выполняй `ls` по тому же пути и смотри, что именно удаляешь.

## 3.4. Переменные окружения и PATH

PATH — список каталогов, где оболочка ищет исполняемые файлы. Именно поэтому работает команда `python`.

```bash
echo $PATH                 # bash
$env:Path                  # PowerShell
export API_KEY="secret"    # bash, на время сессии
$env:API_KEY = "secret"    # PowerShell
```

> [!NOTE] Секреты и настройки передаются через переменные окружения, а не хардкодятся в коде — это принцип 12-Factor Apps. Подробно — главы 21 и 54.

## 3.5. Ускорители работы

- **Tab** — автодополнение имён файлов и команд. Нажимай всегда.
- **Стрелки вверх/вниз** — история команд; `Ctrl+R` — поиск по истории (bash).
- **Ctrl+C** — прервать выполняющуюся программу.
- **Ctrl+L** / `clear` — очистить экран.
- `|` — передать вывод одной команды на вход другой: `ps aux | grep python`.
- `>` — записать вывод в файл (перезапись), `>>` — дописать.

## 3.6. PowerShell и политики выполнения

При активации виртуального окружения PowerShell может запретить скрипт. Лечится один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

# Глава 4. Редактор и IDE

**Цель главы:** настроить среду, которая подсказывает, проверяет и отлаживает код.

## 4.1. Чем писать код

Блокнот не подходит: нет подсветки, автодополнения, проверки ошибок и отладчика. Реальный выбор: **VS Code** (лёгкий, универсальный) или **PyCharm** (тяжёлый, «всё включено» для Python). Начни с VS Code.

## 4.2. VS Code: установка и расширения

1. Скачай с `code.visualstudio.com`, установи.
2. Поставь расширения: **Python** (Microsoft), **Pylance** (анализ и подсказки), **Ruff** (линтер и форматтер).
3. Открой папку проекта: `File → Open Folder`. Работай именно папкой, а не отдельным файлом — так IDE видит контекст проекта.

## 4.3. Выбор интерпретатора

# Глава 5. Первый скрипт: создание, запуск, ошибки

**Цель главы:** написать, запустить и осознанно сломать свою первую программу.

## 5.1. Hello, world

## 5.2. Что произошло при запуске

Оболочка нашла `python` в PATH → интерпретатор прочитал файл → скомпилировал в байт-код → виртуальная машина вызвала встроенную функцию `print` → та записала строку в стандартный поток вывода → терминал показал её. Программа завершилась с кодом 0 (успех).

> [!NOTE] Файл `.py` не является исполняемым сам по себе. Ты всегда запускаешь **интерпретатор**, передавая ему файл как аргумент.

## 5.4. Комментарии, отступы, стиль

### 5.4.1. Комментарии

# Однострочный комментарий: объясняет ЗАЧЕМ, а не ЧТО

### 5.4.2. Отступы — это синтаксис

В Python блоки задаются отступами, а не фигурными скобками. Стандарт PEP 8: **4 пробела** на уровень, табы не использовать.

if True:

> [!WARNING] Смешивание табов и пробелов даёт `TabError`. Включи в редакторе «вставлять пробелы вместо табов».

### 5.4.3. Минимум PEP 8 на старте

Строки до 88 символов, пустая строка между логическими блоками, `snake_case` для переменных и функций, пробелы вокруг `=` и операторов, две пустые строки между функциями верхнего уровня. Автоматизируется Ruff (глава 28).

## 5.5. Три вида ошибок

### 5.5.1. Синтаксическая (SyntaxError)

Код невозможно разобрать. Программа не запускается вообще.

```python

```

### 5.5.2. Ошибка времени выполнения (исключение)

Код корректен, но операция невозможна:

```python
print(10 / 0)       # ZeroDivisionError: division by zero
```

### 5.5.3. Логическая

Программа работает, но результат неверный. Самая опасная: интерпретатор молчит. Лечится тестами (глава 30).

## 5.6. Как читать traceback

```
Traceback (most recent call last):
  File "hello.py", line 7, in <module>
    total = calc(10, 0)
  File "hello.py", line 3, in calc
    return a / b
ZeroDivisionError: division by zero
```

Читать **снизу вверх**:最后一 строка — тип и суть ошибки; выше — точное место (файл, строка, функция); ещё выше — цепочка вызовов, приведшая туда.

> [!TIP] Текст исключения целиком копируй в поисковик, убрав из него свои имена переменных и путей.

## 5.7. Правильная структура скрипта

```python
"""Модуль расчёта итоговой суммы заказа."""


def total(price: float, qty: int) -> float:
    """Вернуть стоимость qty единиц товара по цене price."""
    return price * qty


def main() -> None:
    print(total(1200, 3))


if __name__ == "__main__":
    main()
```

### 5.7.1. Зачем `if __name__ == "__main__"`

При прямом запуске файла Python присваивает переменной `__name__` значение `"__main__"`. При импорте файла как модуля — имя модуля. Условие позволяет иметь код, который выполняется только при запуске, но не при импорте. Это стандарт де-факто для точки входа.

### 5.7.2. Зачем функция `main()`

Локальные переменные внутри функции работают быстрее глобальных, код становится тестируемым, а точка входа — явной. Приучайся сразу.

## 5.8. Кодировка и переносы строк

Файлы Python по умолчанию в UTF-8 (PEP 3120). Сохраняй всегда в UTF-8, переносы — LF. В VS Code это видно в правом нижнем углу. Иначе на другой ОС получишь `UnicodeDecodeError` или шумный git-дифф.

# Глава 6. Переменные, имена и модель памяти

**Цель главы:** понять, что переменная в Python — не «коробка со значением», а имя, привязанное к объекту. Это объясняет половину «странностей» языка.

## 6.1. Присваивание — это привязка

```python
age = 30
name = "Anna"
is_active = True
```

Оператор `=` не копирует значение в ячейку памяти. Он создаёт объект в куче и **привязывает к нему имя** в текущем пространстве имён. Тип принадлежит объекту, а не имени — поэтому одна переменная может последовательно ссылаться на объекты разных типов.

> [!NOTE] Аннотация `age: int = 30` ничего не проверяет в рантайме. Это подсказка для человека и статического анализатора (глава 27).

## 6.2. Правила и соглашения по именам

### 6.2.1. Жёсткие правила

Разрешены буквы (в т.ч. Unicode), цифры и `_`; имя не может начинаться с цифры; нельзя использовать ключевые слова (`class`, `def`, `if`, ...). Регистр значим: `age` и `Age` — разные имена.

### 6.2.2. Соглашения PEP 8

| Стиль | Где применяется | Пример |
|---|---|---|
| `snake_case` | переменные, функции, модули | `total_price` |
| `PascalCase` | классы | `BankAccount` |
| `UPPER_SNAKE` | константы | `MAX_RETRIES` |
| `_leading` | внутреннее, «не трогай» | `_cache` |
| `__leading` | name mangling в классах | `__balance` |

> [!WARNING] Не называй переменные именами встроенных функций: `list`, `dict`, `str`, `sum`, `id`, `type`. Ты затенишь их и получишь загадочный `TypeError` через 20 строк.

## 6.3. Динамическая типизация

```python
x = 10        # x ссылается на int
x = "ten"     # теперь на str — это законно
print(type(x))  # <class 'str'>
```

Проверять тип нужно через `isinstance(x, int)`, а не `type(x) == int` — первый учитывает наследование.

## 6.4. Модель объекта: id, type, value

У каждого объекта есть три характеристики: **идентичность** (`id()` — в CPython адрес в памяти), **тип** (`type()`) и **значение**.

### 6.4.1. `==` против `is`

`==` сравнивает значения (вызывает `__eq__`), `is` — идентичность (тот же самый объект).

```python
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)   # True  — значения равны
print(a is b)   # False — объекты разные
```

### 6.4.2. Кэширование малых чисел и интернирование строк

CPython кэширует int от −5 до 256 и интернирует некоторые строки, поэтому `is` иногда «случайно» работает. Это деталь реализации, а не правило языка.

> [!NOTE] Единственный корректный сценарий `is` — сравнение с синглтонами: `if x is None`, `if flag is True`. Для значений всегда `==`.

## 6.5. Ссылки и изменяемость

### 6.5.1. Mutable и immutable

Неизменяемые: `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`. Изменяемые: `list`, `dict`, `set`, `bytearray`, большинство экземпляров классов.

### 6.5.2. Эффект совместной ссылки

```python
a = [1, 2]
b = a           # то же самое имя для того же объекта
b.append(3)
print(a)        # [1, 2, 3] — изменился и a!
```

С числами и строками такого не бывает: «изменение» создаёт новый объект, потому что старый изменить нельзя.

### 6.5.3. Копирование

```python
import copy

shallow = a.copy()          # поверхностная: новый список, те же элементы
deep = copy.deepcopy(matrix)  # рекурсивная копия вложенных структур
```

> [!WARNING] Поверхностная копия списка списков копирует только внешний список. Вложенные списки останутся общими — классический баг в матрицах и конфигах.

## 6.6. Приёмы присваивания

```python
a, b = 1, 2            # множественное
a, b = b, a            # обмен без временной переменной
x = y = 0              # цепочка (осторожно с mutable!)
first, *rest = [1, 2, 3, 4]   # распаковка со звёздочкой

if (n := len(data)) > 10:     # моржовый оператор, Python 3.8+
    print(n)

del a                  # удалить привязку имени (не обязательно объект)
```

> [!WARNING] `grid = [[]] * 3` создаёт три ссылки на **один** список. Правильно: `grid = [[] for _ in range(3)]`.

## 6.7. Константы

В Python нет настоящих констант. Есть соглашение: `UPPER_SNAKE` означает «не менять». Для типизированных констант используется `typing.Final` (глава 27).

# Глава 7. Числа: int, float, Decimal, Fraction

**Цель главы:** научиться выбирать правильный числовой тип и не терять деньги на округлениях.

## 7.1. Целые числа (int)

`int` в Python 3 не ограничен разрядностью — размер зависит только от памяти. Переполнения не бывает.

```python
big = 2 ** 1000
population = 1_400_000_000   # подчёркивания для читаемости
hex_color = 0xFF             # 255
octal, binary = 0o17, 0b1010
```

## 7.2. Арифметические операторы

| Оператор | Смысл | Пример | Результат |
|---|---|---|---|
| `+ - *` | сложение, вычитание, умножение | `7 * 3` | `21` |
| `/` | истинное деление, всегда float | `7 / 2` | `3.5` |
| `//` | целочисленное деление (вниз) | `-7 // 2` | `-4` |
| `%` | остаток | `-7 % 2` | `1` |
| `**` | возведение в степень | `2 ** 10` | `1024` |
| `divmod(a, b)` | пара (частное, остаток) | `divmod(7, 2)` | `(3, 1)` |

> [!NOTE] `//` округляет **вниз**, а не к нулю. Для отрицательных чисел это отличается от C и Java. Знак `%` совпадает со знаком делителя.

Приоритет: `**` выше унарного минуса, выше `* / // %`, выше `+ -`. `**` правоассоциативен: `2 ** 3 ** 2` = `2 ** 9` = 512.

## 7.3. Дробные числа (float) и их пределы

### 7.3.1. Почему 0.1 + 0.2 != 0.3

`float` — это IEEE-754 двойной точности, двоичная дробь. Числа 0.1 и 0.2 в двоичной системе бесконечны и хранятся приближённо.

```python
print(0.1 + 0.2)                 # 0.30000000000000004
print(0.1 + 0.2 == 0.3)          # False
```

### 7.3.2. Как сравнивать правильно

```python
import math
math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9)   # True
```

### 7.3.3. Округление

`round()` использует банковское округление — к ближайшему чётному: `round(2.5)` = 2, `round(3.5)` = 4. Это уменьшает систематическую ошибку при суммировании, но удивляет новичков.

> [!WARNING] Никогда не храни деньги во `float`. Ошибка накопится и приведёт к расхождению баланса. Только `Decimal` или целые копейки.

## 7.4. Decimal — точная десятичная арифметика

```python
from decimal import Decimal, getcontext, ROUND_HALF_UP

getcontext().prec = 28
price = Decimal("19.99")     # строка! не Decimal(19.99)
total = price * 3
print(total)                                  # 59.97
print(total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
```

> [!NOTE] `Decimal(0.1)` унаследует двоичную погрешность float. Создавай `Decimal` из строки или int.

## 7.5. Fraction и complex

```python
from fractions import Fraction
print(Fraction(1, 3) + Fraction(1, 6))   # 1/2 — точная рациональная арифметика

z = 3 + 4j
print(z.real, z.imag, abs(z))            # 3.0 4.0 5.0
```

`Fraction` удобен в учебных и точных расчётах, `complex` — в инженерных и научных задачах. В типичном backend не встречаются.

## 7.6. Модули math и random

# Глава 8. Строки и текст

**Цель главы:** уверенно работать с текстом — самой частой数据类型 в backend.

## 8.1. Создание строк

s1 = 'одинарные'

строка"""

Экранирование: `\n` — перевод строки, `\t` — табуляция, `\\` — обратный слэш, `\"` — кавычка, `\u00e9` — Unicode-символ.

## 8.2. Индексация и срезы

```python
s = "Python"
s[0]      # 'P'
s[-1]     # 'n'
s[1:4]    # 'yth'  — срез [start:stop:step], stop не включается
s[::-1]   # 'nohtyP'
s[:3]     # 'Pyt'
```

Срез никогда не выходит за границы и не бросает `IndexError` — в отличие от одиночного индекса.

## 8.3. Неизменяемость

```python
s = "cat"
s[0] = "b"        # TypeError
s = "b" + s[1:]   # создаётся НОВЫЙ объект
```

Все методы строк возвращают новую строку, а не меняют исходную. `s.upper()` без присваивания — бесполезная операция.

## 8.4. Основные методы

| Метод | Что делает |
|---|---|
| `.upper() / .lower() / .title()` | регистр |
| `.strip() / .lstrip() / .rstrip()` | убрать пробелы (или указанные символы) |
| `.split(sep) / .rsplit(sep, maxsplit)` | строка → список |
| `sep.join(iterable)` | список → строка |
| `.replace(old, new, count)` | замена подстроки |
| `.find(x) / .index(x)` | позиция (`-1` против исключения) |
| `.startswith(x) / .endswith(x)` | проверка префикса/суффикса |
| `.count(x)` | число вхождений |
| `.isdigit() / .isalpha() / .isspace()` | проверки символов |
| `.zfill(n) / .ljust(n) / .center(n)` | выравнивание и дополнение |

```python
words = "a,b,c".split(",")
print("-".join(words))          # a-b-c
print("  hi  ".strip())         # 'hi'
```

## 8.5. Форматирование: f-строки

```python
name, amount = "Anna", 1234.5678
print(f"{name}: {amount:.2f} ₽")
print(f"{amount=}")             # amount=1234.5678 — отладочный синтаксис
print(f"{42:>10}|")             # выравнивание вправо
print(f"{255:#x}")              # 0xff
print(f"{0.1234:.1%}")          # 12.3%
print(f"{1234567:,}")           # 1,234,567
```

| Спецификатор | Значение |
|---|---|
| `:.2f` | 2 знака после запятой |
| `:>10` / `:<10` / `:^10` | выравнивание в поле ширины 10 |
| `:05d` | целое с ведущими нулями |
| `:,` | разделитель тысяч |
| `:.1%` | процент |
| `:#x` / `:b` / `:o` | hex / binary / octal |

> [!TIP] f-строки — единственный современный способ. `.format()` и `%` встретишь в старом коде; знать надо, писать — нет.

## 8.6. Unicode, bytes и кодировки

### 8.6.1. str против bytes

`str` — последовательность Unicode-символов (абстракция). `bytes` — последовательность байтов (физическое представление). Мост между ними — кодировка, обычно UTF-8.

```python
text = "Привет"
raw = text.encode("utf-8")     # b'\xd0\x9f...'
back = raw.decode("utf-8")
print(len(text), len(raw))     # 6 12 — символов 6, байтов 12
```

### 8.6.2. Кракозябры

`ÐŸÑ€Ð¸Ð²ÐµÑ‚` — это UTF-8, прочитанный как Latin-1. Лечение — всегда явно указывать `encoding="utf-8"` при чтении файлов и не полагаться на локаль ОС.

> [!WARNING] `UnicodeDecodeError` при чтении файла не решай через `errors="ignore"` — это молчаливая потеря данных. Сначала выясни реальную кодировку (например, `cp1251`).

## 8.7. Производительность и типичные ошибки

```python
# плохо: O(n²), на каждой итерации новая строка
s = ""
for w in words:
    s += w

# хорошо: O(n)

```

Частые ошибки новичка: забыть присвоить результат метода; сравнивать строки с числами; использовать `is` вместо `==`; путать `find` (−1) и `index` (исключение).

# Глава 9. Логический тип, truthiness и приведение типов

**Цель главы:** понять, как Python принимает решения и где скрываются ловушки приведения.

## 9.1. bool и None

`bool` имеет ровно два значения: `True` и `False`. Технически это подкласс `int` (`True == 1`). `None` — отдельный синглтон, означающий «значения нет». Это не `0`, не `""` и не `False`.

```python
result = None
if result is None:
    print("ещё не вычислено")
```

## 9.2. Truthiness: что считается ложью

В логическом контексте (`if`, `while`, `and`, `or`, `not`) любой объект приводится к bool. Ложны:

| Значение | Пример |
|---|---|
| `None` | `if x:` |
| `False` | |
| Нули любых числовых типов | `0`, `0.0`, `Decimal("0")` |
| Пустые последовательности | `""`, `[]`, `()`, `b""` |
| Пустые отображения и множества | `{}`, `set()` |

Всё остальное — истинно, включая `"0"`, `"False"`, `[0]` и `[[]]`.

> [!WARNING] `bool("False")` → `True`, потому что строка непустая. Ответ пользователя из `input()` нельзя проверять как bool.

> [!TIP] Пиши `if not items:` вместо `if len(items) == 0:` — это идиоматично. Но если нужно отличить `None` от пустого списка, проверяй явно: `if items is None`.

## 9.3. Логические операторы

### 9.3.1. Короткое замыкание

`and` возвращает первый ложный операнд или последний; `or` — первый истинный или последний. Возвращается **объект**, а не bool.

```python
print(0 or "default")     # 'default'
print("a" and "b")        # 'b'
name = user_input or "Гость"
```

Правая часть не вычисляется, если результат уже определён — на этом строится защита: `if user is not None and user.is_active:`.

### 9.3.2. Приоритет

`not` выше `and`, `and` выше `or`. В сложных условиях ставь скобки — читаемость важнее краткости.

## 9.4. Сравнения

```python
1 < 2 < 3            # цепочка, эквивалент (1 < 2) and (2 < 3)
"a" < "b"            # лексикографически по код-поинтам
[1, 2] < [1, 3]      # поэлементно
```

`==` вызывает `__eq__` и может быть переопределён; `!=` — его отрицание. Операторы `<`, `>` требуют реализации соответствующих протоколов (глава 24).

## 9.5. Приведение типов

```python
int("42")        # 42
int("42.5")      # ValueError! сначала float, потом int
float("3.14")    # 3.14
str(42)          # '42'
bool("")         # False
list("abc")      # ['a', 'b', 'c']
```

Явное приведение бросает `ValueError` или `TypeError` при невозможности — это надо обрабатывать (глава 19). Неявное приведение Python делает только в арифметике (int → float → complex), но не между строкой и числом: `"1" + 1` → `TypeError`.

## 9.6. Тернарное выражение

```python
status = "активен" if user.is_active else "заблокирован"
```

Используй для простых случаев. Вложенные тернарники нечитаемы — заменяй на `if/elif`.

# Глава 10. Ввод и вывод: консольное взаимодействие

**Цель главы:** научиться получать данные от пользователя и корректно выводить результат.

## 10.1. print подробно

```python
print("a", "b", sep="-", end="!\n")     # a-b!
print("загрузка...", end="", flush=True)
import sys
print("ошибка", file=sys.stderr)
```

- `sep` — разделитель аргументов (по умолчанию пробел);
- `end` — что печатать в конце (по умолчанию `\n`);
- `file` — поток вывода;
- `flush` — сбросить буфер немедленно (нужно для прогресс-индикаторов).

> [!NOTE] `print()` — инструмент отладки и CLI. В серверном коде используется логирование (глава 29), потому что print не имеет уровней, времени и структуры.

## 10.2. input и валидация

`input()` **всегда возвращает строку**, даже если ввели число.

```python
raw = input("Возраст: ")
age = int(raw)          # может бросить ValueError
```

Надёжный шаблон ввода:

```python
def ask_int(prompt: str, min_value: int, max_value: int) -> int:
    while True:
        raw = input(prompt).strip()
        try:
            value = int(raw)
        except ValueError:
            print("Нужно целое число, попробуйте снова.")
            continue
        if not (min_value <= value <= max_value):
            print(f"Диапазон: {min_value}..{max_value}.")
            continue
        return value
```

> [!TIP] Валидируй ввод на границе системы. Внутри программы должны циркулировать уже проверенные данные — это принцип «parse, don't validate», к которому мы вернёмся в главе 47 на Pydantic.

## 10.3. Потоки и коды возврата

У процесса есть три стандартных потока: stdin (0), stdout (1), stderr (2). Обычный результат идёт в stdout, диагностика и ошибки — в stderr. Это позволяет перенаправлять их раздельно.

```python
import sys
sys.exit(1)     # ненулевой код = ошибка; так реагируют CI и shell-скрипты
```

## 10.4. Аргументы командной строки

import sys

```

`sys.argv[0]` — имя скрипта, далее — аргументы, все строки. Для настоящих CLI используется `argparse` (глава 35), а не ручной разбор.

## 10.5. Мини-проект главы

```python
"""Консольный калькулятор чаевых."""
from decimal import Decimal, ROUND_HALF_UP


def tips(amount: Decimal, percent: int) -> Decimal:
    return (amount * percent / 100).quantize(Decimal("0.01"), ROUND_HALF_UP)


def main() -> None:
    amount = Decimal(input("Сумма счёта: ").replace(",", "."))
    percent = int(input("Процент чаевых: "))
    tip = tips(amount, percent)
    print(f"Чаевые: {tip}")
    print(f"Итого:  {amount + tip}")


if __name__ == "__main__":
    main()
```

Разбери построчно: где границы системы, где чистая логика, где точка входа. Функция `tips` не знает о консоли — её можно протестировать и переиспользовать в API. Это первый шаг к архитектуре.
