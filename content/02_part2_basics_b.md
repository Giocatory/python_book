
# Глава 11. Ветвления: принятие решений

**Цель главы:** научиться выражать логику выбора так, чтобы код читался сверху вниз без «стрелы» из вложенных условий.

## 11.1. Управление потоком выполнения

По умолчанию инструкции выполняются последовательно. Ветвление позволяет выполнить только часть кода в зависимости от условия. Условием может быть **любой объект** — он приводится к bool по правилам главы 9.

## 11.2. if / elif / else

```python
balance = 1500

if balance < 0:
    print("Перерасход")
elif balance == 0:
    print("Пусто")
else:
    print("Есть средства")
```

### 11.2.1. Как это работает

Python проверяет условия **сверху вниз** и выполняет только первую истинную ветку, остальные пропускает. `elif` может быть сколько угодно, `else` — не более одного и всегда последний. Блок задаётся отступом в 4 пробела.

### 11.2.2. Порядок условий имеет значение

Если поставить широкое условие раньше узкого, узкая ветка никогда не выполнится:

```python
# НЕВЕРНО: вторая ветка недостижима
if amount > 0:
    ...
elif amount > 1000:
    ...
```

> [!NOTE] Правило: сначала частные случаи, потом общие. Это же правило действует для `except` (глава 19) и `match` (11.6).

## 11.3. Guard clauses: ранний выход

Вместо вложенности переворачивай условие и выходи из функции сразу.

```python
# плохо: три уровня вложенности
def pay(user, amount):
    if user is not None:
        if user.is_active:
            if amount > 0:
                return do_pay(user, amount)
    return None


# хорошо: плоская структура
def pay(user, amount):
    if user is None:
        return None
    if not user.is_active:
        return None
    if amount <= 0:
        return None
    return do_pay(user, amount)
```

> [!TIP] Каждый уровень вложенности увеличивает нагрузку на рабочую память читателя. Плоский код с ранними возвратами — стандарт промышленной разработки.

## 11.4. Тернарное выражение и словарная диспетчеризация

```python
label = "доход" if amount > 0 else "расход"

ACTIONS = {"add": add_op, "list": list_ops, "report": report}
action = ACTIONS.get(command)
if action is None:
    print("Неизвестная команда")
else:
    action()
```

Длинная цепочка `elif`, сравнивающая одну переменную с константами, почти всегда заменяется словарём. Это быстрее, короче и расширяется добавлением записи, а не правкой логики.

## 11.5. match / case: структурное сопоставление (3.10+)

### 11.5.1. Базовый синтаксис

```python
match command:
    case "add":
        add_operation()
    case "quit" | "exit":
        raise SystemExit
    case _:
        print("Неизвестная команда")
```

`match` — не аналог `switch` из C. Он умеет разбирать **структуру** данных, а не только сравнивать значения. `_` — шаблон по умолчанию, связывающий что угодно.

### 11.5.2. Шаблоны последовательностей и словарей

```python
match event:
    case {"type": "income", "amount": amount}:
        print(f"Доход {amount}")
    case {"type": "expense", "amount": amount, "category": cat}:
        print(f"Расход {amount} в {cat}")
    case [x, y]:
        print(f"Координаты {x}, {y}")
    case str() as text:
        print(f"Просто строка: {text}")
```

Шаблон словаря проверяет **наличие** ключей, лишние ключи игнорируются. Имена в шаблоне связываются со значениями — это деструктуризация.

### 11.5.3. Охранники (guards)

```python
match operation:
    case {"amount": a} if a > 100_000:
        require_approval()
    case {"amount": a}:
        process()
```

> [!WARNING] Одиночное имя в `case` — это **связывание**, а не сравнение с переменной. `case expected:` совпадёт всегда. Для сравнения используй точечное имя: `case Status.ACTIVE:`.

## 11.6. Типичные ошибки

- `=` вместо `==` в условии (синтаксическая ошибка, но новички путают смысл).
- Условие `if x == True:` вместо `if x:`.
- Проверка `if len(items) > 0` вместо `if items`.
- Забытый `else`, из-за которого переменная остаётся неопределённой.
- Цепочка из 15 `elif` там, где нужен словарь или `match`.

# Глава 12. Циклы: повторение действий

**Цель главы:** уверенно обходить коллекции, управлять ходом цикла и не создавать бесконечных петель.

## 12.1. Цикл while

```python
count = 0
while count < 3:
    print(count)
    count += 1
```

Условие проверяется **перед** каждой итерацией. Если оно ложно сразу — тело не выполнится ни разу.

> [!WARNING] Забытое изменение переменной в теле даёт бесконечный цикл. Прервать — `Ctrl+C` (`KeyboardInterrupt`).

`while` уместен, когда число итераций заранее неизвестно: чтение до маркера, ожидание события, игровой/меню-цикл.

## 12.2. Цикл for и протокол итерации

```python
for item in ["a", "b", "c"]:
    print(item)
```

`for` не «считает счётчик», как в C. Он получает итератор из объекта (`iter()`), затем многократно вызывает `next()`, пока не получит `StopIteration` (подробно — глава 18). Поэтому `for` работает со списками, строками, словарями, файлами, генераторами и любыми итерируемыми объектами.

## 12.3. range

```python
range(5)          # 0,1,2,3,4
range(2, 6)       # 2,3,4,5
range(0, 10, 2)   # 0,2,4,6,8
range(10, 0, -1)  # 10..1
```

`range` ленив: он не создаёт список в памяти, а хранит три числа и вычисляет элементы на лету. `list(range(1_000_000))` займёт десятки мегабайт, сам `range(1_000_000)` — байты.

> [!NOTE] Правая граница не включается — как и в срезах. Это согласованное правило всего языка: `stop` всегда исключается.

## 12.4. break, continue и else

```python
for op in operations:
    if op.amount == 0:
        continue          # перейти к следующей итерации
    if op.amount < -100_000:
        print("Подозрительная операция")
        break             # выйти из цикла немедленно
else:
    print("Все операции проверены")   # выполнится, если break НЕ сработал
```

`else` у цикла — уникальная черта Python. Читается как «если не нашли». Идеален для поиска:

```python
for op in operations:
    if op.id == target_id:
        found = op
        break
else:
    found = None
```

> [!TIP] `else` после цикла избавляет от флага `found = False`. Но если код с `else` смущает команду — вынеси поиск в функцию с ранним `return`.

## 12.5. Правильные способы обхода

```python
for i, item in enumerate(items, start=1):   # индекс + значение
    print(i, item)

for name, price in zip(names, prices):      # параллельный обход
    print(name, price)

for item in reversed(items):                # в обратном порядке
    ...

for key in sorted(prices):                  # в отсортированном порядке
    ...
```

> [!WARNING] Конструкция `for i in range(len(items))` с последующим `items[i]` — признак того, что нужен `enumerate`. Пиши идиоматично.

`zip` останавливается по самой короткой последовательности. Если длины должны совпадать — используй `zip(a, b, strict=True)` (3.10+), он бросит `ValueError` при расхождении.

## 12.6. Изменение коллекции во время итерации

```python
# НЕВЕРНО: пропуск элементов
for x in items:
    if x < 0:
        items.remove(x)

# верно: итерируемся по копии
for x in items[:]:
    if x < 0:
        items.remove(x)

# лучше: создаём новый список
items = [x for x in items if x >= 0]
```

Удаление сдвигает элементы, а внутренний указатель итератора продолжает идти вперёд — часть данных пропускается. Для словарей изменение размера во время обхода даёт `RuntimeError`.

## 12.7. Вложенные циклы и сложность

Двойной цикл по n элементов даёт O(n²): при 10 000 элементов это 100 млн итераций. Если внутренняя задача — поиск, замени внутренний цикл на словарь или множество (O(1) вместо O(n)).

```python
# было O(n²)
for op in operations:
    for cat in categories:
        if op.category_id == cat.id:
            ...

# стало O(n)
cats_by_id = {c.id: c for c in categories}
for op in operations:
    cat = cats_by_id.get(op.category_id)
```

Для выхода из двух циклов сразу: вынеси их в функцию и используй `return`, либо `itertools.product`.

## 12.8. Обход словаря и файла

```python
for key, value in totals.items():

with open("operations.csv", encoding="utf-8") as f:

```

# Глава 13. Списки и кортежи

**Цель главы:** понять, как устроен список в памяти, и научиться выбирать операции по их стоимости.

## 13.1. Что такое list внутри

`list` — **динамический массив указателей** на объекты, а не массив самих значений. Отсюда два следствия: элементы могут быть любых типов, и любой элемент требует разыменования (медленнее, чем массив чисел в C). При заполнении массив периодически перевыделяется с запасом, поэтому добавление в конец амортизированно O(1).

| Операция | Сложность | Комментарий |
|---|---|---|
| `lst[i]`, `len(lst)` | O(1) | прямой доступ по смещению |
| `append`, `pop()` | O(1) амортизированно | конец массива |
| `insert(0, x)`, `pop(0)` | O(n) | сдвиг всех элементов |
| `x in lst`, `index`, `count` | O(n) | линейный поиск |
| `remove(x)` | O(n) | поиск плюс сдвиг |
| `sort` | O(n log n) | Timsort, устойчивая |
| срез `lst[a:b]` | O(k) | создаёт новый список |

> [!NOTE] Если часто добавляешь и удаляешь с обоих концов — это `collections.deque`, а не `list`. У неё O(1) с обеих сторон.

## 13.2. Создание, индексы, срезы

```python
nums = [1, 2, 3]
empty = []
from_range = list(range(5))
chars = list("abc")

nums[0], nums[-1]
nums[1:]  = [9, 9]      # срезовое присваивание: замена участка
nums[::2] = [0, 0]      # шаг тоже допустим
del nums[1:3]
```

Срез всегда создаёт **новый** список (поверхностная копия элементов).

## 13.3. Методы списка

| Метод | Действие | Возвращает |
|---|---|---|
| `append(x)` | добавить один элемент в конец | `None` |
| `extend(iterable)` | добавить все элементы iterable | `None` |
| `insert(i, x)` | вставить по индексу | `None` |
| `remove(x)` | удалить первое вхождение по значению | `None` |
| `pop(i=-1)` | извлечь и вернуть элемент | элемент |
| `clear()` | очистить | `None` |
| `index(x)` | позиция первого вхождения | `int` или `ValueError` |
| `count(x)` | число вхождений | `int` |
| `sort(key=..., reverse=...)` | сортировка на месте | `None` |
| `reverse()` | разворот на месте | `None` |
| `copy()` | поверхностная копия | новый `list` |

> [!WARNING] Все мутирующие методы возвращают `None`. Классический баг: `items = items.append(x)` — после этого `items` равен `None`.

Разница `append` и `extend`:

```python
a = [1, 2]
a.append([3, 4])   # [1, 2, [3, 4]]
b = [1, 2]
b.extend([3, 4])   # [1, 2, 3, 4]
```

## 13.4. Сортировка

```python
sorted(ops)                      # новый список, исходный не тронут
ops.sort()                       # на месте, экономит память

ops.sort(key=lambda o: o.amount, reverse=True)

from operator import attrgetter, itemgetter
ops.sort(key=attrgetter("date", "amount"))   # по двум полям
rows.sort(key=itemgetter(1))
```

Сортировка **устойчивая**: элементы с равным ключом сохраняют исходный порядок. Поэтому можно сортировать последовательно по второстепенному, затем по главному ключу.

> [!TIP] `key` вызывается ровно один раз на элемент (декорирование Шварца), поэтому `sort(key=...)` заметно быстрее устаревшего `cmp`.

## 13.5. Копии и ловушки

```python
b = a               # то же имя объекта
b = a[:]            # поверхностная копия
b = a.copy()        # то же самое
b = copy.deepcopy(a)  # рекурсивная копия

grid = [[]] * 3     # ОШИБКА: три ссылки на один список
grid = [[] for _ in range(3)]   # правильно
```

## 13.6. Кортежи (tuple)

```python
point = (10, 20)
single = (5,)          # запятая обязательна, иначе это просто 5 в скобках
no_parens = 1, 2, 3    # скобки не обязательны
x, y = point           # распаковка
```

### 13.6.1. Зачем нужен кортеж

- **Неизменяемость** как гарантия: функция не сможет испортить данные.
- **Хэшируемость**: кортеж можно положить в `set` или сделать ключом `dict` (если все элементы хэшируемы).
- **Семантика записи**: кортеж — это «строка данных» фиксированной структуры, список — однородная коллекция переменной длины.
- Меньше памяти и чуть быстрее создание.

### 13.6.2. Неизменяемость поверхностная

```python
t = ([1, 2], 3)
t[0].append(9)     # законно! изменился список внутри
print(t)           # ([1, 2, 9], 3)
hash(t)            # TypeError: список нехэшируем
```

> [!NOTE] Кортеж гарантирует, что **ссылки** не изменятся, а не что неизменны сами объекты.

### 13.6.3. Именованные кортежи

```python
from collections import namedtuple
Op = namedtuple("Op", "date amount category")
op = Op("2026-11-24", 1500, "food")
print(op.amount)
```

Это переходный шаг к `dataclass` (глава 25): читаемый доступ по имени при той же дешевизне.

# Глава 14. Словари и множества

**Цель главы:** освоить структуры с доступом O(1) — главный инструмент оптимизации в Python.

## 14.1. Как устроен dict

`dict` — хэш-таблица. По ключу вычисляется хэш, он определяет позицию в таблице. Поэтому поиск, вставка и удаление в среднем **O(1)** независимо от размера.

Требования к ключу: он должен быть **хэшируемым** — иметь `__hash__` и согласованный `__eq__`. Практически: неизменяемые типы (`str`, `int`, `float`, `bool`, `tuple` из хэшируемых, `frozenset`). Список ключом быть не может.

> [!NOTE] С Python 3.7 словарь **гарантированно** сохраняет порядок вставки. Это часть спецификации языка, а не деталь реализации.

Коллизии (разные ключи с одинаковым слотом) разрешаются открытой адресацией; в худшем случае операции деградируют до O(n), но на практике это экзотика.

## 14.2. Создание и доступ

```python
prices = {"coffee": 200, "tea": 150}
empty = {}
from_pairs = dict([("a", 1), ("b", 2)])
from_kw = dict(coffee=200, tea=150)

prices["coffee"]        # 200
prices["water"]         # KeyError!
prices.get("water")     # None
prices.get("water", 0)  # 0 — значение по умолчанию
```

> [!TIP] `get` с дефолтом — основной способ безопасного чтения. Но не злоупотребляй: если отсутствие ключа — ошибка логики, пусть `KeyError` упадёт громко.

## 14.3. Изменение

```python
prices["water"] = 100          # вставка или обновление
prices.update({"tea": 160})    # массовое обновление
prices |= {"juice": 250}       # оператор слияния (3.9+)
merged = prices | {"juice": 250}   # новый словарь

del prices["tea"]
value = prices.pop("tea", None)    # извлечь с дефолтом
prices.clear()
```

### 14.3.1. setdefault и defaultdict

```python
groups = {}
for op in operations:
    groups.setdefault(op.category, []).append(op)

from collections import defaultdict
groups = defaultdict(list)
for op in operations:
    groups[op.category].append(op)     # ключ создаётся автоматически
```

> [!WARNING] `defaultdict` создаёт ключ при **любом** обращении, даже при чтении. Проверка `if key in dd` безопасна, а `dd[key]` — уже мутация.

## 14.4. Обход словаря

```python
for key in prices:                 # по ключам (по умолчанию)
for key in prices.keys():          # то же явно
for value in prices.values():
for key, value in prices.items():  # идиоматичный способ
```

`keys()`, `values()`, `items()` — это **представления** (views), а не копии: они отражают изменения словаря в реальном времени и не тратят память на список.

## 14.5. Counter и вложенные структуры

```python
from collections import Counter

counter = Counter(op.category for op in operations)
print(counter.most_common(3))     # топ-3 категории
counter["food"] += 1

totals = defaultdict(lambda: defaultdict(float))
totals["2026-11"]["food"] += 1500
```

## 14.6. Множества: set и frozenset

```python
tags = {"food", "taxi", "food"}    # {'food', 'taxi'} — дедупликация
empty = set()                      # {} — это пустой СЛОВАРЬ, не множество!
```

Операции (в коде, а не в таблице, чтобы символы не путались):

```python
a = {"food", "taxi"}
b = {"taxi", "shop"}

a.union(b)                  # объединение: food, taxi, shop
a.intersection(b)           # пересечение: taxi
a.difference(b)             # разность: food
a.symmetric_difference(b)   # ровно в одном: food, shop
a.issubset(b)               # подмножество?
a.add("health")
a.discard("taxi")           # без ошибки, если нет
a.remove("taxi")            # KeyError, если нет
```

Для операторов (`|`, `&`, `-`, `^`) оба операнда должны быть множествами; методы принимают любой итерируемый объект.

### 14.6.1. Зачем множества

- Дедупликация: `list(set(items))` (порядок не сохраняется).
- Проверка вхождения O(1) вместо O(n) у списка.
- Сравнение наборов: «какие категории новые», «какие пропали».

`frozenset` — неизменяемое множество, хэшируемо, годится в ключи словаря.

> [!WARNING] Порядок элементов в `set` не гарантирован и может меняться между запусками (для строк — из-за рандомизации хэша). Никогда не полагайся на него.

## 14.7. Какую структуру выбрать

| Задача | Структура |
|---|---|
| Упорядоченная последовательность, дубликаты допустимы | `list` |
| Фиксированная запись, неизменяемость, ключ словаря | `tuple` |
| Доступ по ключу, справочник, счётчик | `dict` |
| Уникальность, проверка вхождения, операции над наборами | `set` |
| Очередь с двух концов | `collections.deque` |

# Глава 15. Comprehensions и генераторные выражения

**Цель главы:** писать компактные и быстрые преобразования коллекций, не превращая их в нечитаемую однострочную головоломку.

## 15.1. Списковое включение

```python
squares = [x * x for x in range(10)]
amounts = [op.amount for op in operations]
```

Читается как «список из `x*x` для каждого `x` в `range(10)`». Это не «синтаксический сахар ради краткости»: comprehension выполняется быстрее эквивалентного цикла с `append`, потому что не делает вызов метода на каждой итерации.

## 15.2. Фильтрация и условное выражение

```python
# фильтр в конце: какие элементы взять
expenses = [op for op in operations if op.amount < 0]

# тернарник в начале: что положить в результат
labels = ["доход" if op.amount > 0 else "расход" for op in operations]

# вместе
labels = ["доход" if op.amount > 0 else "расход"
          for op in operations if op.amount != 0]
```

> [!NOTE] Запомни позицию: `if` **после** `for` — это фильтр (может отбросить элемент). `if/else` **до** `for` — это выражение выбора значения (элемент будет всегда).

## 15.3. Вложенные циклы и выравнивание

```python
pairs = [(x, y) for x in range(3) for y in range(3) if x != y]
flat = [item for row in matrix for item in row]
```

Порядок `for` — как в обычных вложенных циклах: слева внешний, справа внутренний.

> [!TIP] Больше двух `for` или двух `if` в одном comprehension — сигнал вынести логику в функцию с говорящим именем. Читаемость важнее краткости.

## 15.4. Словарные и множественные включения

```python
by_id = {op.id: op for op in operations}
totals = {cat: sum_by(cat) for cat in categories}
unique_cats = {op.category for op in operations}
inverted = {v: k for k, v in prices.items()}
```

Последний пример теряет данные при дублирующихся значениях — помни об этом при инвертировании словаря.

## 15.5. Генераторные выражения

```python
gen = (x * x for x in range(10))       # круглые скобки вместо квадратных
total = sum(op.amount for op in operations)   # скобки вызова уже есть
```

Круглые скобки создают **генератор**: он не строит коллекцию в памяти, а выдаёт элементы по одному. Разница на больших данных драматическая:

```python
sum([x * x for x in range(10_000_000)])   # список ~400 МБ
sum(x * x for x in range(10_000_000))     # десятки байт
```

> [!NOTE] Правило: если результат сразу передаётся в `sum`, `any`, `all`, `max`, `min`, `join`, `sorted` — используй генераторное выражение, а не список. Промежуточная коллекция не нужна.

Генератор **одноразовый**: после исчерпания он пуст. Обойти его дважды нельзя (глава 18).

## 15.6. Моржовый оператор в включениях

```python
results = [y for op in operations if (y := expensive(op)) > 0]
```

Позволяет не вызывать дорогую функцию дважды. Применяй умеренно: это уже пограничная зона читаемости.

## 15.7. Антипаттерны

- Comprehension ради побочного эффекта: `[print(x) for x in items]` — создаёт бесполезный список из `None`. Нужен обычный `for`.
- Три уровня вложенности в одной строке.
- `list(...)` вокруг генератора, который тут же обходится один раз.
- Логика с исключениями внутри comprehension — выноси в функцию.

## 15.8. Контрольные вопросы

1. Где ставится фильтр, а где условное выражение?
2. Чем генераторное выражение отличается от спискового по памяти?
3. Почему `[print(x) for x in items]` — плохой код?

# Глава 16. Функции: основы декомпозиции

**Цель главы:** научиться разрезать программу на осмысленные, тестируемые и переиспользуемые куски.

## 16.1. Зачем нужны функции

Функция решает четыре задачи: даёт имя фрагменту логики (читаемость), устраняет дублирование (DRY), изолирует состояние (локальные переменные) и создаёт единицу тестирования. Функция, которую нельзя протестировать отдельно, — почти всегда плохо спроектированная функция.

## 16.2. Определение и вызов

```python
def total(price: float, qty: int) -> float:
    """Вернуть стоимость qty единиц товара."""
    return price * qty

result = total(1200, 3)
```

`def` создаёт объект-функцию и привязывает к нему имя. Тело не выполняется в момент определения — только при вызове.

### 16.2.1. return и None

`return` немедленно завершает функцию и отдаёт значение. Без `return` (или с голым `return`) функция возвращает `None`. Можно вернуть несколько значений — на самом деле это кортеж:

```python
def stats(values):
    return min(values), max(values), sum(values)

lo, hi, s = stats([1, 2, 3])
```

## 16.3. Параметры и аргументы

**Параметры** — имена в определении, **аргументы** — значения при вызове.

```python
def transfer(source, target, amount, comment=""):
    ...

transfer("A", "B", 100)                       # позиционные
transfer(source="A", target="B", amount=100)  # именованные
transfer("A", target="B", amount=100)         # смешанные
```

> [!NOTE] После именованного аргумента позиционный идти не может: `transfer(source="A", "B", 100)` — SyntaxError.

## 16.4. Значения по умолчанию и главная ловушка Python

```python
def add_op(op, operations=[]):     # ОПАСНО
    operations.append(op)
    return operations
```

Значения по умолчанию вычисляются **один раз при определении функции**, а не при каждом вызове. Изменяемый дефолт живёт между вызовами:

```python
print(add_op("a"))   # ['a']
print(add_op("b"))   # ['a', 'b'] — сюрприз
```

Правильный шаблон:

```python
def add_op(op, operations=None):
    if operations is None:
        operations = []
    operations.append(op)
    return operations
```

> [!WARNING] Это самый частый вопрос на собеседовании Junior и самый частый скрытый баг в реальном коде. Дефолтами могут быть только неизменяемые объекты.

## 16.5. *args и **kwargs

```python
def log(level, *args, **kwargs):
    print(level, args, kwargs)

log("INFO", "started", "db", user="anna", retries=3)
# INFO ('started', 'db') {'user': 'anna', 'retries': 3}
```

`*args` собирает лишние позиционные аргументы в кортеж, `**kwargs` — лишние именованные в словарь. Имена `args`/`kwargs` — соглашение, значимы только звёздочки.

Обратная операция — распаковка при вызове:

```python
values = [1200, 3]
total(*values)

params = {"price": 1200, "qty": 3}
total(**params)
```

## 16.6. Разделители / и *

```python
def create_user(name, /, *, email, is_active=True):
    ...
```

- Всё **до `/`** — только позиционные (нельзя передать по имени).
- Всё **после `*`** — только именованные.

Зачем: позиционные-only позволяют менять имена параметров без ломки клиентского кода; keyword-only запрещают нечитаемые вызовы вида `create_user("anna", True, False)`.

> [!TIP]布尔 флаги и вообще более двух аргументов делай keyword-only. `pay(user, amount, *, notify=True, dry_run=False)` читается несравнимо лучше.

## 16.7. Аннотации типов

```python
def convert(amount: Decimal, rate: float = 1.0) -> Decimal:
    ...
```

Аннотации не проверяются в рантайме — это документация и вход для mypy/pyright (глава 27). Ставь их с первого дня: это привычка, которая позже экономит недели отладки.

## 16.8. Docstrings (PEP 257)

```python
def split_bill(total: Decimal, people: int) -> list[Decimal]:
    """Разделить счёт на равные части без потери копеек.

    Args:
        total: итоговая сумма счёта.
        people: количество участников, больше нуля.

    Returns:
        Список сумм, длина равна people, сумма элементов равна total.

    Raises:
        ValueError: если people меньше единицы.
    """
```

Первая строка — краткое повелительное описание («Разделить», а не «Функция делит»). Docstring доступен через `help()` и `func.__doc__`, из него собираются Swagger-описания в FastAPI.

## 16.9. Признаки хорошей функции

- Делает одну вещь и умещается на экран (ориентир — до 20–30 строк).
- Имеет имя-глагол: `calculate_total`, а не `data` или `process2`.
- Не смешивает уровни абстракции: бизнес-логика не читает `input()` внутри себя.
- Минимум побочных эффектов: ввод-вывод вынесен на границы (глава 10).
- Не более 3–4 параметров; больше — признак того, что нужен объект или `dataclass`.

# Глава 17. Области видимости, замыкания и декораторы

**Цель главы:** понять, откуда берутся имена, и освоить главный инструмент метапрограммирования Python.

## 17.1. Правило LEGB

Поиск имени идёт по четырём областям: **L**ocal (текущая функция) → **E**nclosing (объемлющая функция) → **G**lobal (модуль) → **B**uilt-in (встроенные).

```python
x = "global"

def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)     # local
    inner()
```

> [!NOTE] Тело класса **не** является enclosing-областью для методов. Метод не видит атрибуты класса по имени — только через `self` или `ClassName`.

## 17.2. global и nonlocal

```python
counter = 0

def bump():
    global counter
    counter += 1

def outer():
    count = 0
    def inner():
        nonlocal count
        count += 1
    inner()
    return count
```

Без объявления присваивание создаёт **новую локальную** переменную, а чтение внешней при этом упадёт с `UnboundLocalError`.

> [!WARNING] `global` — почти всегда признак плохого дизайна. Заменяй глобальное состояние параметром, возвращаемым значением или атрибутом объекта. `nonlocal` легитимен в замыканиях и фабриках декораторов.

## 17.3. Замыкания

Замыкание — функция, которая помнит переменные объемлющей области даже после её завершения.

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor
    return multiply

double = make_multiplier(2)
print(double(10))          # 20
print(double.__closure__[0].cell_contents)   # 2
```

### 17.3.1. Ловушка позднего связывания

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])      # [2, 2, 2], а не [0, 1, 2]

funcs = [lambda i=i: i for i in range(3)]   # фиксация через дефолт
print([f() for f in funcs])      # [0, 1, 2]
```

Замыкание хранит **переменную**, а не её значение на момент создания. К моменту вызова цикл уже завершился.

## 17.4. Функции первого класса

Функцию можно присвоить переменной, положить в коллекцию, передать аргументом и вернуть.

```python
def apply(func, value):
    return func(value)

apply(str.upper, "abc")

handlers = {"income": handle_income, "expense": handle_expense}
sorted(ops, key=lambda o: o.amount)
list(map(abs, amounts))
list(filter(None, values))     # отбросить все ложные значения
```

`lambda` — анонимная функция из **одного выражения**. Уместна как `key` или короткий колбэк; для логики с условиями и несколькими строками используй `def`.

## 17.5. Декораторы

Декоратор — функция, принимающая функцию и возвращающая новую, обычно с добавленным поведением.

```python
import functools
import time


def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f"{func.__name__}: {time.perf_counter() - start:.4f}s")
    return wrapper


@timed
def build_report():
    ...
```

Запись `@timed` эквивалентна `build_report = timed(build_report)`.

> [!NOTE] `@functools.wraps(func)` обязателен: он копирует `__name__`, `__doc__`, `__module__` и ставит ссылку `__wrapped__`. Без него отладчик, Sphinx, FastAPI и pytest увидят вместо вашей функции безымянный `wrapper`.

## 17.6. Декораторы с параметрами

Три уровня вложенности: фабрика принимает параметры, декоратор принимает функцию, обёртка принимает аргументы вызова.

```python
def retry(times: int = 3, delay: float = 0.5):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except ConnectionError:
                    if attempt == times:
                        raise
                    time.sleep(delay * attempt)
        return wrapper
    return decorator


@retry(times=5)
def fetch_rates():
    ...
```

Порядок применения: декораторы применяются **снизу вверх**, ближайший к `def` — первым.

## 17.7. Готовые декораторы стандартной библиотеки

```python
from functools import cache, lru_cache, singledispatch

@cache                       # безусловное кэширование (3.9+)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

@lru_cache(maxsize=1024)     # с ограничением размера
def get_rate(code): ...

@singledispatch              # перегрузка по типу первого аргумента
def render(value): ...
```

> [!WARNING] `lru_cache` держит ссылки на аргументы и результаты — это утечка памяти при неограниченном множестве ключей и «залипание» при работе с изменяемыми данными. Не кэшируй методы с `self` бездумно.

# Глава 18. Итераторы, генераторы и контекстные менеджеры

**Цель главы:** освоить ленивые вычисления — основу работы с большими данными и всего asyncio.

## 18.1. Iterable и Iterator

- **Iterable** (итерируемый) — объект с методом `__iter__`, который возвращает итератор. Список, словарь, строка, файл.
- **Iterator** (итератор) — объект с `__next__`, возвращающим следующий элемент, и `__iter__`, возвращающим себя. Когда элементы кончились, бросает `StopIteration`.

```python
items = [1, 2, 3]
it = iter(items)      # получаем итератор
next(it)              # 1
next(it)              # 2
next(it)              # 3
next(it)              # StopIteration
```

> [!NOTE] Список можно обходить многократно — каждый `iter()` даёт новый итератор. Итератор одноразов: он «сгорает» после прохода. Это ключевое различие.

## 18.2. Что делает for на самом деле

```python
# for x in obj: body
# эквивалентно:
it = iter(obj)
while True:
    try:
        x = next(it)
    except StopIteration:
        break
    # body
```

Именно поэтому `for` работает с чем угодно, что реализует протокол, — включая сетевые потоки и бесконечные последовательности.

## 18.3. Свой итератор

```python
class Countdown:
    def __init__(self, start: int):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1
```

Класс нужен, когда у обхода есть сложное состояние. В 95% случаев достаточно генератора.

## 18.4. Генераторы: yield

```python
def countdown(start: int):
    while start > 0:
        yield start
        start -= 1

for n in countdown(3):
    print(n)
```

Функция с `yield` при вызове **не выполняется** — она возвращает объект-генератор. Тело исполняется до ближайшего `yield` при каждом `next()`, затем **замораживается** вместе со всеми локальными переменными и точкой исполнения.

> [!NOTE] Генератор — это функция с сохраняемым состоянием. Именно на этом механизме построены корутины и весь `asyncio` (глава 37).

## 18.5. Экономия памяти и конвейеры

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")

def parse(lines):
    for line in lines:
        date, amount, cat = line.split(",")
        yield (date, float(amount), cat)

def only_expenses(rows):
    for row in rows:
        if row[1] < 0:
            yield row

pipeline = only_expenses(parse(read_lines("operations.csv")))
total = sum(row[1] for row in pipeline)
```

Файл на 10 ГБ обрабатывается за константную память: в каждый момент в памяти одна строка. Это базовый паттерн ETL и потоковой обработки.

## 18.6. send, throw, close и yield from

```python
def accumulator():
    total = 0
    while True:
        value = yield total
        if value is None:
            break
        total += value

gen = accumulator()
next(gen)          # запуск до первого yield
gen.send(10)       # 10
gen.send(5)        # 15
gen.close()        # GeneratorExit внутри генератора
```

`yield from iterable` делегирует итерацию другому генератору, пробрасывая значения и исключения. Сегодня это в основном внутренности `asyncio` и рефакторинг вложенных генераторов.

## 18.7. itertools — стандартная библиотека ленивости

```python
from itertools import chain, islice, groupby, product, count, takewhile

chain(list1, list2)            # склейка без копирования
islice(gen, 10)                # первые 10 из бесконечного потока
product([1, 2], "ab")          # декартово произведение
count(1)                       # бесконечный счётчик
takewhile(lambda x: x < 5, nums)

# groupby требует ПРЕДВАРИТЕЛЬНОЙ сортировки по тому же ключу
for cat, group in groupby(sorted(ops, key=attrgetter("category")),
                          key=attrgetter("category")):
    print(cat, sum(o.amount for o in group))
```

> [!WARNING] `groupby` группирует только **соседние** элементы с одинаковым ключом. Без сортировки получишь несколько групп одной категории.

## 18.8. Контекстные менеджеры

### 18.8.1. Протокол with

```python
with open("data.txt", encoding="utf-8") as f:
    data = f.read()
# файл закрыт даже при исключении внутри блока
```

`with` вызывает `__enter__` на входе и `__exit__` на выходе — гарантированно, включая случаи исключения и `return`.

### 18.8.2. Свой менеджер через генератор

```python
from contextlib import contextmanager

@contextmanager
def transaction(session):
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()
```

Всё до `yield` — вход, всё после — выход. Ровно один `yield` обязателен.

### 18.8.3. Полезное из contextlib

```python
from contextlib import suppress, ExitStack

with suppress(FileNotFoundError):
    os.remove(path)

with ExitStack() as stack:
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]
```

`ExitStack` управляет динамическим числом ресурсов — то, что не выразить одним `with a, b, c`.

# Глава 19. Исключения и обработка ошибок

**Цель главы:** научиться отличать recoverable-ошибки от багов и строить предсказуемую политику отказов.

## 19.1. Иерархия

```
BaseException
 ├── SystemExit
 ├── KeyboardInterrupt
 ├── GeneratorExit
 └── Exception
      ├── ValueError
      ├── TypeError
      ├── KeyError / IndexError / AttributeError
      ├── OSError (FileNotFoundError, PermissionError, ...)
      └── RuntimeError, StopIteration, ...
```

> [!NOTE] `KeyboardInterrupt` и `SystemExit` наследуются от `BaseException`, а не `Exception` — специально, чтобы `except Exception` их не перехватывал и программу можно было остановить.

## 19.2. Полная конструкция

```python
try:
    value = int(raw)
except ValueError as exc:
    print(f"Не число: {exc}")
except (TypeError, KeyError):
    print("Другая проблема")
else:
    print("Выполнится, только если исключений не было")
finally:
    print("Выполнится всегда: освобождение ресурса")
```

- `except` — обработка;
- `else` — код, который должен выполняться только при успехе (не попадает под защиту `try`, что важно);
- `finally` — гарантированная очистка.

## 19.3. Ловить конкретное

```python
# ПЛОХО
try:
    do_something()
except:
    pass

# ХОРОШО
try:
    rate = rates[code]
except KeyError:
    rate = DEFAULT_RATE
```

> [!WARNING] `except:` без типа и `except Exception: pass` — главные источники «тихих» продакшен-инцидентов. Они глотают опечатки в именах, `KeyboardInterrupt` и ошибки логики. Программа продолжает работать в повреждённом состоянии.

## 19.4. raise и цепочки исключений

```python
try:
    amount = Decimal(raw)
except InvalidOperation as exc:
    raise ValidationError(f"Некорректная сумма: {raw!r}") from exc
```

`from exc` заполняет `__cause__` и печатает «The above exception was the direct cause...». Без него Python всё равно сохранит контекст в `__context__`, но явная цепочка expresses намерение.

Голый `raise` внутри `except` пробрасывает текущее исключение дальше, сохраняя traceback.

## 19.5. Свои исключения

```python
class FinanceError(Exception):
    """Базовая ошибка домена."""


class InsufficientFunds(FinanceError):
    def __init__(self, balance: Decimal, amount: Decimal):
        self.balance, self.amount = balance, amount
        super().__init__(f"Недостаточно средств: {balance} < {amount}")


class CurrencyNotSupported(FinanceError):
    pass
```

Правило: одна базовая ошибка на пакет/домен, наследники — конкретные ситуации. Тогда вызывающий код может ловить как конкретику, так и всё семейство разом. В FastAPI это напрямую превращается в обработчики и HTTP-коды (глава 48).

## 19.6. EAFP против LBYL

**LBYL** (Look Before You Leap): проверить, потом сделать. **EAFP** (Easier to Ask Forgiveness than Permission): сделать, поймать исключение.

```python
# LBYL — есть гонка между проверкой и действием
if os.path.exists(path):
    os.remove(path)

# EAFP — идиоматично для Python
try:
    os.remove(path)
except FileNotFoundError:
    pass
```

Python предпочитает EAFP: исключения дёшевы, когда не возникают, и защищают от состояния гонки.

## 19.7. Исключения и границы системы

Правило слоёв: внутри домена бросаем доменные исключения; на границе (HTTP-хендлер, CLI, консьюмер очереди) переводим их во внешний формат — HTTP-код, сообщение пользователю, nack в брокер. Никогда не показывай пользователю traceback и текст внутреннего исключения.

## 19.8. ExceptionGroup и except* (3.11+)

При параллельном выполнении нескольких задач может упасть сразу несколько. Для этого есть группы:

```python
try:
    async with asyncio.TaskGroup() as tg:
        ...
except* ValueError as eg:
    for exc in eg.exceptions:
        ...
```

Подробно — в главе 37, здесь важно знать, что такая конструкция существует.

> [!WARNING] `asyncio.CancelledError` наследуется от `BaseException` и не должен проглатываться. Обработал — обязательно `raise`. Иначе задача не отменится и приложение зависнет при shutdown.

# Глава 20. Модули и пакеты

**Цель главы:** научиться组织 структуру проекта так, чтобы импорты работали из любой точки запуска.

## 20.1. Модуль — это файл

`finance/utils.py` — модуль `utils`. Импорт выполняет **весь код верхнего уровня** файла один раз и кэширует результат в `sys.modules`. Повторный `import` берёт готовый объект.

```python
import math
import finance.utils as utils
from finance.utils import format_money
from decimal import Decimal as D
```

> [!WARNING] `from module import *` засоряет пространство имён и затирает существующие имена. Допустимо только в интерактивной сессии.

## 20.2. Пакеты

Пакет — каталог с модулями. Классический пакет содержит `__init__.py` (может быть пустым), который выполняется при импорте пакета и задаёт его публичный API.

```
finance/
    __init__.py
    models.py
    storage.py
    reports.py
```

```python
# finance/__init__.py
from finance.models import Operation
from finance.reports import total_by_category

__all__ = ["Operation", "total_by_category"]
```

Существуют также namespace-пакеты без `__init__.py` (PEP 420) — для распределённых пакетов; в обычном проекте используй классические.

## 20.3. sys.path и почему «модуль не найден»

При запуске `python path/to/script.py` в `sys.path[0]` попадает **каталог скрипта**. При запуске `python -m package.module` — **текущий каталог**. Отсюда классическая проблема: файл работает при прямом запуске и ломается при импорте.

> [!NOTE] Правильное решение — не хаки с `sys.path.append`, а установка проекта в окружение (`uv sync` / `pip install -e .`, глава 21) и запуск через `python -m finance.cli`.

## 20.4. Абсолютные и относительные импорты

```python
from finance.storage import save      # абсолютный — предпочтительно
from .storage import save             # относительный внутри пакета
from ..core import settings
```

Относительные импорты работают только внутри пакета и ломаются при запуске файла напрямую. В приложении используй абсолютные.

## 20.5. Циклические импорты

`a.py` импортирует `b.py`, а `b.py` импортирует `a.py` → `ImportError: cannot import name ... (most likely due to a circular import)`.

Способы лечения по убыванию правильности:
1. Вынести общую часть в третий модуль (`types.py`, `models.py`) — устраняет причину.
2. Пересмотреть зависимости: цикл почти всегда означает нарушение границ слоёв.
3. Импорт внутри функции — локальный обход, допустим точечно.
4. Для аннотаций — `from __future__ import annotations` и блок `if TYPE_CHECKING:`.

```python
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from finance.storage import Storage    # только для анализатора, не в рантайме
```

## 20.6. Структура проекта: src-layout

```
finance-app/
    pyproject.toml
    .python-version
    src/
        finance/
            __init__.py
            cli.py
            models.py
            storage.py
            reports.py
    tests/
        test_reports.py
```

Преимущество `src/`: невозможно случайно импортировать код из текущей директории — тесты всегда проверяют **установленный** пакет, как это будет у пользователя.

## 20.7. Точка входа

```python
# src/finance/cli.py
def main() -> None:
    ...

if __name__ == "__main__":
    main()
```

Плюс запись в `pyproject.toml`:

```toml
[project.scripts]
finance = "finance.cli:main"
```

После установки появляется команда `finance` — так делают все профессиональные CLI-инструменты.

# Глава 21. Виртуальные окружения и управление зависимостями

**Цель главы:** получить детерминированную, воспроизводимую сборку проекта — то, без чего код не доедет до продакшена.

## 21.1. Зачем изоляция

Все пакеты, поставленные глобально, попадают в один каталог `site-packages`. Проект A требует `pydantic<2`, проект B — `pydantic>=2`. Одновременно они не уживутся. Виртуальное окружение — отдельный каталог со своим интерпретатором-ссылкой и своим `site-packages`.

> [!NOTE] Правило без исключений: **один проект — одно окружение**. Никогда не ставь рабочие зависимости в системный Python.

## 21.2. venv: базовый инструмент

```bash
python -m venv .venv

source .venv/bin/activate          # Linux / macOS
.\.venv\Scripts\Activate.ps1       # Windows PowerShell

python -m pip install requests
deactivate
```

Внутри `.venv` лежат `bin`/`Scripts`, `lib/site-packages` и `pyvenv.cfg` с путём к базовому интерпретатору. Каталог `.venv` добавляется в `.gitignore` — он воспроизводим из lock-файла.

> [!TIP] Активация лишь правит PATH. Можно вообще не активировать: `.venv/bin/python -m pytest` работает так же. Это удобно в скриптах и CI.

## 21.3. pip и requirements.txt

```bash
python -m pip install "requests>=2.31,<3"
python -m pip install -r requirements.txt
python -m pip freeze > requirements.txt
python -m pip list --outdated
```

Ограничения подхода: `freeze` сваливает в кучу прямые и транзитивные зависимости, не различает dev и prod, не решает конфликты версий и не даёт хэшей. Для учебного скрипта годится, для сервиса — нет.

## 21.4. pyproject.toml — современный стандарт

```toml
[project]
name = "finance"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "httpx>=0.27",
    "pydantic>=2.7",
]

[project.optional-dependencies]
postgres = ["sqlalchemy>=2.0", "asyncpg>=0.29"]

[dependency-groups]
dev = ["pytest>=8", "pytest-cov", "mypy>=1.10", "ruff>=0.5"]

[project.scripts]
finance = "finance.cli:main"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

`[project]` — метаданные по PEP 621, `[dependency-groups]` — группы для разработки по PEP 735. Это единая точка правды о проекте.

## 21.5. uv: рабочий процесс

```bash
uv init finance-app          # создать проект с pyproject.toml
uv python install 3.13       # поставить нужный интерпретатор
uv add httpx pydantic        # добавить зависимость (обновит pyproject и lock)
uv add --dev pytest ruff mypy
uv sync                      # привести .venv в точное соответствие uv.lock
uv run python -m finance.cli # запуск в окружении без активации
uv run pytest
uv lock --upgrade            # обновить зафиксированные версии
```

`uv` написан на Rust, работает на порядки быстрее pip и заменяет собой сразу venv, pip, pip-tools, pyenv и poetry. На 2026 год это де-факто стандарт новых Python-проектов.

> [!NOTE] `uv.lock` коммитится в git для приложений (детерминированный деплой) и обычно не коммитится для библиотек (они должны работать с диапазоном версий).

## 21.6. Poetry и PDM

Poetry — предшественник uv с похожей моделью (`poetry add`, `poetry install`, `poetry.lock`). Встречается во множестве существующих проектов, знать нужно. PDM — ещё один менеджер с поддержкой PEP 582. Новые проекты начинай на uv.

## 21.7. Версии и детерминизм

SemVer: `MAJOR.MINOR.PATCH`. Спецификаторы:

| Запись | Смысл |
|---|---|
| `==2.7.0` | ровно эта версия |
| `>=2.7,<3` | диапазон, исключая мажорный слом |
| `~=2.7.0` | совместимые релизы: `>=2.7.0,<2.8` |
| без ограничения | рискованно, сборка невоспроизводима |

Прямые зависимости задаются диапазоном в `pyproject.toml`, а **точное** дерево версий фиксируется в lock-файле. Именно lock обеспечивает одинаковое поведение на ноутбуке, в CI и в продакшене.

## 21.8. Фиксация версии Python

Файл `.python-version` с содержимым `3.13` читается uv и pyenv и гарантирует, что все разработчики и CI используют одну минорную версию. Дополнительно версия указывается в `requires-python` и в базовом образе Docker (глава 54).
